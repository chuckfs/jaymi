Non-Goals

A clear vision requires clear boundaries.

Jaymi is an ambitious project.

That makes it easy to continually add new ideas without finishing the existing ones.

This document defines what Jaymi is not trying to accomplish during its current stages of development.

These are not permanent decisions.

They are priorities.

Current focus (see `ROADMAP.md`): deepen Layers 7–8 (tools and real providers), wire Reasoning when ready, and grow workspace UX toward Layer 9 — without expanding the non-goals below.

⸻

Jaymi Is Not Building a Language Model

Jaymi is not an LLM.

The project does not aim to train or compete with frontier AI models.

Instead, Jaymi focuses on:

* Context
* Memory
* Planning
* Tool orchestration
* User experience

Language models are providers—not the product.

⸻

Jaymi Is Not an Operating System

Jaymi runs on top of existing operating systems.

It is not attempting to replace macOS, Windows, or Linux.

Building a desktop environment or operating system may be explored in the future, but it is explicitly outside the current scope.

⸻

Jaymi Is Not Trying to Replace Every Application

Jaymi should integrate with existing software before replacing it.

Whenever possible:

* Connect first.
* Replace later.

Existing applications are valuable tools.

Jaymi coordinates them.

⸻

Jaymi Is Not Tied to Any AI Provider

No provider is considered “the default.”

No architecture should depend on:

* a specific model
* a specific company
* a specific API
* a specific cloud service

Everything should remain replaceable.

⸻

Jaymi Is Not Cloud Dependent

Cloud capabilities are optional.

The application should remain functional without an internet connection.

Internet access is treated as a capability—not a requirement.

⸻

Jaymi Is Not Fully Autonomous

Jaymi should assist users.

Not replace them.

Potentially destructive actions should require review and approval.

Automation should always remain transparent.

⸻

Jaymi Is Not a Surveillance Tool

Jaymi should never silently monitor the user’s computer.

Indexing, importing, and data collection should be visible, configurable, and under the user’s control.

The user decides what Jaymi knows.

⸻

Jaymi Is Not a Feature Race

Success is not measured by:

* Number of models
* Number of providers
* Number of integrations
* Number of features

Every feature must solve a real problem.

Features should exist because they improve the experience—not because another application has them.

⸻

Jaymi Does Not Optimize for Benchmarks

Benchmark scores are not the goal.

The goal is helping users accomplish real work.

A smaller model with excellent context is often more useful than a larger model without context.

⸻

Jaymi Does Not Assume Infinite Hardware

The architecture should scale.

The software should remain usable on consumer hardware.

New hardware should improve performance—not be required for functionality.

⸻

Jaymi Does Not Sacrifice Simplicity

Adding a feature should not significantly increase complexity.

If a simpler solution exists that satisfies the architecture, it should be preferred.

Complexity must be justified.

⸻

Jaymi Does Not Lock In User Data

Users should always be able to:

* Export memories
* Export projects
* Export conversations
* Remove providers
* Delete data

Knowledge belongs to the user.

Never to Jaymi.

⸻

Jaymi Does Not Guess When It Can Know

Whenever possible, Jaymi should retrieve information rather than invent it.

Search first.

Read second.

Reason third.

Answers should be grounded in evidence whenever available.

⸻

Jaymi Does Not Build Everything at Once

The project grows through small, complete milestones.

Every milestone should produce a usable improvement.

Architectural quality is more important than development speed.

⸻

Current Priorities

The current focus is:

* Planner
* Context Engine
* Memory
* Search
* Projects
* Provider Framework
* Tool Framework
* Desktop Experience

Everything else builds on top of these foundations.

⸻

Future Possibilities

The following ideas are intentionally deferred until the core architecture is stable:

* Voice-first interaction
* Mobile applications
* Multi-agent collaboration
* Robotics
* Wearables
* Smart home integration
* Desktop environment
* Operating system
* Distributed inference
* Real-time collaboration

These are possibilities—not commitments.

⸻

A Final Reminder

Whenever a new feature is proposed, ask:

Does this make Jaymi a better personal AI environment?

If the answer is no, it does not belong.

If the answer is not yet, write it down and return to the current milestone.

Great software is defined as much by what it refuses to do as by what it chooses to build.
